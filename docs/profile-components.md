# Profile components

The profile uses linked SVG components. GitHub sanitizes arbitrary page CSS and JavaScript; layout uses native image wrapping instead of a document table. Each project tile is an independent link. The 400px image width permits two desktop columns and a natural single mobile column. The hero and activity widget have dedicated mobile compositions.

Static imagery is pinned to its asset commit through jsDelivr, so existing GitHub Camo caches do not show mismatched versions. The design assets are repository-owned; no public statistics rendering endpoint is required. Titles in the static components use outlined Sora letterforms (OFL license in assets/showcase). Technology marks use Simple Icons v16 (CC0). Image alt text describes each destination.

`scripts/update_profile.py` queries public GitHub repositories and the user's contribution calendar. It renders an activity chart and a sampled language byte distribution, writes a public aggregate snapshot, and updates only generated-asset URLs in README when passed an immutable asset revision. Repository language shares are code composition, not proficiency; forks are excluded, and only the five largest languages per repository are sampled. The last 12 calendar-month bars may show partial first/current periods. The yearly contribution total is the GitHub calendar total and is labelled separately from commits.

The workflow runs daily at 09:17 Beijing time and on manual dispatch. It requires only this repository's standard GITHUB_TOKEN, with contents write to publish its generated files. It does not require a personal token. On API failure it leaves existing assets intact and fails the workflow. The workflow commits generated assets first, then points the README at that immutable revision, avoiding stale CDN snapshots. GitHub may disable scheduled workflows in inactive public repositories after 60 days; manual dispatch restores fresh widgets.
